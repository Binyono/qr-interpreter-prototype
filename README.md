# QR同時通訳（プロトタイプ）

QRコードを読み取るだけで参加できる、**受信機いらずのリアルタイムAI同時通訳**です。
ガイド（話す人）のスマホ1台と、参加者のスマホだけで動きます。アプリのインストールもログインも不要。
静的ファイル（HTML/CSS/JS）だけでできているので、Netlify Drop にフォルダをドラッグ＆ドロップすればそのままHTTPSで公開できます。

```
index.html   … 画面（ガイド／参加者）
style.css    … 見た目（モバイルファースト）
app.js       … 通信・音声認識・翻訳・読み上げ
vendor/      … PeerJS と QRコード生成ライブラリ（同梱）
README.md    … このファイル
```

---

## 1. すぐ試す

### A. Netlify Drop で公開する（おすすめ・2分）

1. https://app.netlify.com/drop を開く
2. このフォルダ（`qr-interpreter` フォルダ、または `qr-interpreter-prototype.zip`）をドラッグ＆ドロップ
3. 発行された `https://xxxx.netlify.app` のURLを開く
4. 「配信を開始（QRを表示）」を押す

> マイクは **HTTPS のページでしか使えません**。`file://` でローカルのHTMLを開くと、QRもマイクも動きません（画面は出ます）。

### B. ローカルで動かす

```bash
cd qr-interpreter
python3 -m http.server 8000
# → http://localhost:8000
```
`localhost` はマイクが使える例外的なオリジンです。同じWi-Fi内の別端末から見る場合は、HTTPS公開（A）にしてください。

### C. 2台での動作テスト手順

1. **1台目（ガイド）**：サイトを開き「配信を開始」。部屋コード（例 `K7M2QP`）とQRが出ます。
2. **2台目（参加者）**：カメラでQRを読み取る → URLが開く → 言語（English など）を選ぶ。
3. 1台目で **マイク** を押して話す。または、マイクが使えない環境なら「マイクが使えない時は…」の入力欄に日本語を入れて **送信**。
4. 2台目に、翻訳字幕が出て、選んだ言語で読み上げが始まります（初回だけ「音声を有効にする」をタップ）。
5. 1台目の「ライブ字幕」に、日本語と各言語の訳、接続人数がリアルタイムで出ます。

## 2. 画面と機能

### ガイド（配信）モード

| 機能 | 内容 |
|---|---|
| 配信開始 | ワンタップで部屋を作り、参加用URLのQRを表示 |
| 部屋コード | 6桁。`?room=XXXXXX` のURLでも参加可能 |
| マイク | ON/OFF。Web Speech API（`ja-JP`・連続認識・中間結果表示） |
| 途中文字のリアルタイム配信 | 認識途中の文を **300〜450ms 間隔**で参加者へ送信（一文が終わるのを待たない） |
| 区切り最適化（低遅延） | **息継ぎ0.75秒 / 20文字前後**で短く区切ってすぐ翻訳（設定で 400〜1500ms・10〜60文字に変更可） |
| 話し続けでも即翻訳 | 話し続けて `isFinal` が来ないブラウザ（Android Chrome等）でも、未確定の途中文を強制的に区切って翻訳へ回す：約35文字（句読点・助詞・空白があればそこで切る）／20文字以上で0.75秒変化が止まったとき／句読点の直後。確定済みの先頭は差し引いて二重訳・欠落を防ぐ |
| 先行翻訳モード | ONで、話している途中の認識結果から訳を先に作る（デバウンス0.25秒）。訳ができた瞬間に参加者のライブ行へ反映し、確定と同時に訳が出る |
| 高精度音声認識 | OpenAIキー設定時、数秒ごとの録音を `gpt-transcribe` 系APIへ送信 |
| 手入力送信 | マイクが使えない環境のテスト用（日本語を直接送る） |
| ライブ字幕 | 「今話した日本語」＋言語ごとの訳＋接続中の人数・言語内訳 |
| 参加者への再送 | 途中参加・言語変更した人には直近の字幕をその言語で送り直す |
| ゲストからの質問 | **📩 ゲストからの質問**パネル。届いた質問をその場で日本語に自動翻訳して「[言語名] 原文／日本語訳」で新しい順に表示。「✓ 済」で消せる。**質問受付 ON/OFF**（既定ON）は接続中の全ゲストへ即時同期。**🔇 質問を読み上げ**（既定OFF）をONにすると、日本語訳をガイドの端末から読み上げる |

### 参加者（受信）モード — `?room=XXXXXX`

- 言語を選ぶだけ（英語・中国語 簡体/繁体・韓国語・スペイン語・フランス語・ドイツ語・ポルトガル語・イタリア語・タイ語・ベトナム語・インドネシア語の12言語）
- ガイドが話し始めた瞬間から、**話している途中の日本語（と先行訳）**が点線枠の「同時通訳中」行にリアルタイムで更新される
- 原文が確定した瞬間に「翻訳中…」で表示し、訳が届くと差し替え（同時通訳らしい見え方）。先行翻訳が当たっていれば待ち時間なしで訳が出る
- **字幕は常に最新へ自動スクロール追従**：喋っている間もどんどん下へ流れ、最新が常に見える。過去を読み返すために大きく上へスクロールしたときだけ追従を止め、右下に「最新へ ↓」が出る（押すと戻って自動追従を再開）
- 表示切替：翻訳＋原文／訳だけ（大きく）／原文だけ、文字サイズ4段階
- **音声 ON/OFF**：端末の `speechSynthesis` で翻訳を読み上げ。**押した瞬間に、選択中の言語で短い確認音声（例：英語なら "Sound on"、韓国語なら「소리 켜짐」）を音量1.0で鳴らす**ので、スピーカーから実際に音が出るかその場で分かる（iOS/Androidの自動再生制限対策も兼ねる）
- 読み上げの無音対策：`list` の音声は**端末内蔵（`localService`）のものだけ**を使い、ネットワーク専用の声しか無い場合は音声を指定せず `u.lang` にOS既定の声を選ばせる（未ダウンロードの声を選んで無音になる実機報告への対処）。`cancel()` 直後の `speak()` が消えるAndroid Chrome対策として **50ms待ってから発話**し、`onend` が来ない端末でも「話し中」のまま固まらないよう保険タイマーを持つ
- **読み上げ速度**：`1.0x / 1.15x / 1.3x` を上部バーでワンタップ切替（同時通訳のテンポに追いつくため）
- **画面消灯よけ**：音声ONの間は Screen Wake Lock（対応端末のみ・失敗しても読み上げは続く）
- 遅れがたまったら古い読み上げを捨てて最新に追いつく（最新2件だけ残す）
- **🎙️ 質問（右下の小さなフローティングボタン）**：文字入力欄は置かない（スマホのキーボードで画面が狭くならないように）。タップすると小さなポップアップが開き、**大きなマイクが点滅（パルス）して音声入力を開始** → 認識した質問がその場で表示 → **話し終わると自動送信**（送信ボタンでも可）→ 送信後は自動で小さいボタンに戻る。**✕ 閉じる**なら送らずに閉じる。ガイドが受付OFFの間はボタンを薄く表示し、押すと「いまは質問を受け付けていません」と**相手の言語**で案内する
- **ゲスト画面は12言語に完全対応**：ボタン・ラベル・案内文・字幕の「● 同時通訳中／聞き取り中…／翻訳中…」まで、選んだ言語（`en` / `zh-CN` / `zh-TW` / `ko` / `es` / `fr` / `de` / `pt` / `it` / `th` / `vi` / `id`）で即座に切り替わる

## 3. 設定（右上の⚙️）

### 翻訳エンジン

| モード | 必要なもの | 用途 |
|---|---|---|
| お試しモード | なし | 接続・QR・字幕・読み上げの一連のテスト。無料の公開翻訳APIを使用（**Google公開エンドポイント優先**、失敗時MyMemory→用語集。精度は本番未満） |
| OpenAI | APIキー | 文脈＋用語集を反映した自然な同時通訳（既定モデル `gpt-6-luna`・変更可） |
| Gemini | APIキー | 同上（既定モデル `gemini-3.5-flash-lite`・変更可） |

- APIキーは**その端末のブラウザ（localStorage）にだけ**保存されます。サーバーには送りません。
- キー未設定でOpenAI/Geminiを選ぶと「キー未設定（お試し動作）」と表示し、お試し翻訳で動きます。
- APIの呼び出しに失敗したときは、その旨を通知して自動でお試し翻訳に切り替えます。

### 固有名詞辞書（カスタム用語集）

「金閣寺 → Kinkaku-ji」「大吟醸 → Daiginjo」のように登録すると、翻訳プロンプトにそのまま入ります（音声認識のヒントにも使用）。イベントごとに登録しておくと誤訳が減ります。

### 音声認識

- **Web Speech API**（既定）：無料・即動く。Android Chrome が得意。
- **高精度API**：OpenAIの `gpt-transcribe` 系（既定 `gpt-transcribe`）。区切り秒数（3〜15秒・既定6秒）で録音して送信。

### 低遅延（同時通訳らしさ）

- **先行翻訳モード（低遅延）**：ONで、話している途中の認識結果が一定以上変わったら**0.25秒**のデバウンスで訳を作っておき、文が確定した瞬間にその訳を出す。ガイド画面の `⚡ 先行翻訳 ON/OFF` か設定シートで切り替え。
  - 確定前でも、訳ができた時点で参加者の「同時通訳中」行に先行訳が届く。
  - 訳を作るのは**接続中の参加者の言語だけ**（聞いている人がいない間はAPIを叩かない）。
  - お試しモードでは呼び出し間隔を**0.35秒**あけて、無料APIを叩きすぎないようにしている。本番はAPIキー設定を推奨。
  - お試しモードの翻訳は **Google公開エンドポイント → MyMemory → 用語集** の順（従来はMyMemory優先で遅かった）。
- **息継ぎで確定（ms）**：既定750。最後の確定結果からこの時間無音なら、そこで一文として確定。
- **区切りの文字数**：既定20。この長さを超えたら文末でなくても区切って翻訳へ回す（短いほど速いが、訳の精度は少し落ちる）。

### 詳細設定

- PeerJSサーバー（空欄なら公式クラウド）
- 追加のICEサーバー（TURN）JSON — 別々の回線でつながらないときの対策（両端末に同じ設定）

## 4. 仕組み

```
ガイド端末                         参加者端末
 マイク → 音声認識 → 日本語テキスト
        ├─ 認識途中の文字（interim） ──→ 「同時通訳中」行に即時更新
        ├─ 途中から先行翻訳（ON時） ──→ 確定前に訳を先出し
        → 翻訳API（言語ごと）
        └─ PeerJS(WebRTC) データチャネル ─→ 字幕表示
                                           └─ 端末の音声合成で読み上げ
```

- **映像・音声そのものは送りません。テキストだけをP2Pで配ります。** 音声は各参加者の端末が合成するので、通信量は非常に小さく、大人数の会議でも回線が詰まりにくいのが利点です。
- サーバーは「シグナリング（接続の仲介）」だけ。PeerJS公式クラウドを使うため、常時起動のバックエンドは不要です。
- 翻訳はガイド端末からAPIへ直接リクエストします（参加者のキーは不要）。
- 外部ライブラリは jsDelivr から取得した同一ファイルを `vendor/` に同梱しています（CDN障害の影響を受けない）。万一 `vendor/` が欠けてもCDNから読み込む二段構えです。

## 5. 動作確認したこと / していないこと

### 確認済み（2026-11-18・v6：音声の同期再生と質問の日本語訳・jsdom **289項目** すべてPASS／単一ファイル版 9項目 PASS）

- **Androidで声が出ない問題**：「音声を有効にする」を押した時の最初の確認音声を、`setTimeout` を挟まず**タップと同じ処理の流れの中で同期的に** `speechSynthesis.speak()` する（テストで固定）。`cancel()` は **発話中／予約中のときだけ**呼び、何も鳴っていない時は呼ばない（無音の `cancel()` が次の発話を殺すのを避ける）。`pumpSpeech()` も `cancel()` 直後以外は待たずに即 `speak()` する。
- **音声データ未導入の案内**：端末から声の一覧は取れているのに、選んだ言語の声が1つも無い場合は、再生は `u.lang` 指定で試みたまま「端末に読み上げ音声が入っていない可能性（設定 → テキスト読み上げで追加）」を一度だけそっと案内する。
- **ゲストの質問の日本語訳**：翻訳元は画面の言語ではなく **`sl=auto`（自動判定）→ `tl=ja`**。英語画面のゲストが日本語で話しても、他言語で話しても日本語に訳す。日本語→日本語の近道は「実際にひらがな・カタカナ・漢字が入っている時だけ」。
- **訳せなかった時に英語を「訳」として出さない**：Google 公開翻訳・MyMemory のどちらも失敗した場合、または入力と同一のテキストが返った場合（英語がそのまま返る症状）は、訳として並べず「⚠️ 日本語に訳せませんでした（原文を確認してください）」と警告色で表示する。MyMemory は `sl=auto` を受け付けない（`'AUTO' IS AN INVALID SOURCE LANGUAGE`）ため、同じ意味の `Autodetect|ja` で問い合わせる。
- **質問パネルの表示**：言語タグ＋`原文` ラベル＋本文の下に `🇯🇵 日本語訳` ラベル付きで訳を出す（原文と訳が上下ではっきり分かれる）。
- `node --check app.js` OK、`index.html` は `style.css?v=6` / `app.js?v=6`

## 6. 制限と注意

- **HTTPS必須**：マイク（`getUserMedia` / Web Speech）はHTTPSかlocalhostでのみ動作。
- **マイクが許可済みなのに「許可されていません」と出る場合**：マイクボタンのタップから `SpeechRecognition.start()` を同期的に呼びます（間に `getUserMedia` を挿みません）。音声認識側のエラーは `not-allowed`（マイク権限）と `service-not-allowed`（端末の音声認識サービス・アプリ内ブラウザ）を区別して出します。表示されたエラー名で原因を切り分けてください。アプリ内ブラウザの場合は右上メニューの「Chromeで開く」、端末の音声入力が無効な場合は設定で「高精度API（Whisper系）」に切り替えるのが早いです。
- **APIキーの扱い**：ブラウザのlocalStorageに保存する簡易方式です。共用端末では使わない、キーは利用制限をかけたものを発行する、などの運用をおすすめします。本番運用では自前のバックエンド経由に置き換えるのが安全です。
- **PeerJS公式クラウド**は無料のデモ用サーバーです。大人数の本番イベントでは、自前のPeerServer（またはTURN付きの構成）に切り替えてください（設定画面の「詳細設定」でホスト指定が可能）。
- **同時接続数**：ガイド端末が全員とP2P接続します。テキストのみなので数十人規模は現実的ですが、数百人規模は配信型（WebSocketサーバー経由）への変更が必要です。
- **翻訳の遅れ**：従来は発話から2〜4秒（確定待ち＋翻訳待ち）。低速延化で、話している途中の日本語は0.3〜0.45秒間隔で届き、訳は先行翻訳モードON＋APIキー設定なら確定直後（0.5秒前後）に出ます。ただしWeb Speech API自体の認識確定には端末側で遅れがあり、音声認識モード（Whisper系）はチャンク単位なので途中表示はありません。
- **お試しモードの翻訳**は無料の公開エンドポイントを使うため、品質・可用性は保証されません。本番はAPIキー設定を前提にしてください。
- 参加者側の言語音声が端末に入っていない場合、読み上げは無音になります（端末の設定から音声を追加）。
- **スピーカーで聴く場合**：スマホのスピーカーからそのまま再生されます（イヤホン不要）。ガイドのマイクが参加者のスピーカー音を拾うとハウリングすることがあるので、距離をとるか音量を調整してください（アプリ側では制限していません）。
